1. What this document covers

This is the record of the German legal-text overhaul carried out on the Gutachten website. It lists every page that was replaced, every page that was newly created, every individual fix that was applied, the items that were already correct and therefore left alone, and the points that are still waiting on an answer from the client.

The work was done from the three source files you supplied (01_AGB.md, 02_Impressum.md, 03_Datenschutzerklaerung.md) plus your numbered fix list. All legal text now lives in one single central file per site, so future wording changes are a one-place edit and never touch the layout.

Scope note: only the SV site was changed. The Facility Management site was not connected to this session, so section 11 of this document is the checklist to apply there later.

3.2 /widerrufsbelehrung — Widerrufsbelehrung

Built as the full statutory scaffold, as agreed, so the page is legally usable today and the client's own text can simply replace it later. It follows the model instruction of Anlage 1 zu Art. 246a § 1 Abs. 2 EGBGB, adapted for services, and includes the Muster-Widerrufsformular. There is a flag in the config (widerrufsbelehrungFinalised) that marks this as pending final client text and legal sign-off.

3.3 One central content file per site

All four legal documents now come out of src/config/legalContent.ts. Nothing legal is hard-coded in a page component any more. A second new file, src/app/components/legal/LegalDocument.tsx, does the rendering and contains no legal wording at all — only layout. That separation is what guarantees the four pages stay visually identical to the rest of the site and to each other.

The qualification block in the Impressum is not duplicated text: it is derived from the existing siteConfig.qualifications data, which is marked in the code as the single source of truth. So a change there propagates to the Impressum automatically.

8. Two deliberate deviations from the source .md files

Both are cases where following the supplied text literally would have published a statement that is untrue for this codebase. They are also documented as comments in the code itself.

  1. Cookie section (Datenschutz section 7). The source text described a consent banner. This website has no consent banner and sets only technically necessary cookies, so the section was rewritten to say exactly that. Publishing the original wording would have described a mechanism that does not exist. If a banner is added later, this section must be rewritten again.
  2. Liability sections kept in the Impressum. 02_Impressum.md omits Haftung für Inhalte, Haftung für Links and Urheberrecht, but your fix item 1 refers to §§ 7–10 DDG, which only appear in those sections. They were therefore retained, already worded under DDG rather than TMG.

9. New finding: services that were not in the questionnaire

While verifying, two third-party data flows turned up in the code that are not mentioned anywhere in the client questionnaire. Both are now disclosed in the Datenschutzerklärung, and both raise questions the client needs to answer.

  • Cloudflare Turnstile is live on the contact page and on the home-page contact form. It processes IP address and browser/device data and involves a US provider. It is now disclosed in section 8 with Art. 6 Abs. 1 lit. f DSGVO as the legal basis and spam defence as the legitimate interest, and Cloudflare is named in section 13 as a third-country transfer.
  • Form submissions do not go straight to an inbox — they are posted to a separate hosted API which then forwards them. That is a processor relationship under Art. 28 DSGVO. Section 8 now describes the flow and offers phone and post as alternatives; the provider's name is held back until confirmed.

Questions to add to the client questionnaire

1. Is there a data processing agreement (AVV) in place with Cloudflare for Turnstile?
2. Who operates the form API, and where are its servers located?
3. Is there an AVV with that operator, and what is the deletion period for submitted form data?
4. Who is the hosting provider, with full address and country, and what is the log file retention period?
5. Is Microsoft 365 (or any other non-EU service) used for mail, calendar or file storage?

12.3 How to edit legal text from now on

Open src/config/legalContent.ts and edit the text of the relevant block. Do not edit the page components: they contain no wording. Content is expressed as typed blocks (paragraph, list, subheading, address, legal-basis note, framed callout), so a new paragraph is one entry in an array and it will automatically match the existing typography. Inline **bold** and [link text](/target) markup is supported and is parsed safely, without raw HTML injection.
